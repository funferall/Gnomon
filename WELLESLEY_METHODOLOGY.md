# Wellesley asset mapping methodology

The active routing-v2 taxonomy covers traffic-control and regulatory signs, street-name signs, signals, bollards/access barriers, hydrants, storm drains and manhole covers. Street furniture such as trash cans, poles, lamps, benches, meters, mailboxes, bicycle racks, cabinets, guardrails and ordinary bus stops is excluded. See REVIEW_AND_BENCHMARK.md for the implemented reviewer, scope migration, benchmark and verification workflow.

## What runs now

`wellesley_pipeline.py` inventories Mapillary images with paginated, resumable small-area requests and a Wellesley polygon filter, and imports Wellesley Panoramax records from the existing snapshot. It keeps provider IDs, timestamps, raw metadata, source references and rights provenance in SQLite. It downloads images on demand, hashes source bytes, creates six perspective views for equirectangular panoramas, runs YOLO-World on CUDA, and retains bounding boxes and enlarged object crops. Failed images remain explicit and can be retried. These are unreviewed camera observations; the assets table is deliberately separate and contains no verified assets yet.

KartaView and Mapilio are not yet inventoried town-wide by this pipeline. Their sequence metadata must be joined to individual photo coordinates and a boundary halo before they can be processed reliably. The current Mapillary catalog queries also need an audit for caps, retries and missing sequences before “all public images” can be asserted. Provider APIs and snapshots cannot establish that every physical asset is observable.

## Processing and completeness ledger

1. Pin a run boundary, inventory cutoff, code/model versions, taxonomy and provider terms. Inventory every capture date, retaining separate image IDs and exact file hashes; flag suspicious timestamps. Add a boundary halo for cameras outside town that can see assets inside it. Store the original image record separately from derived views. Traverse pagination and record per-cell page counts, query errors and last successful cursor. Cross-check with high-resolution coverage tiles and sequence-level enumerations; subdivide cells that hit caps. Date-range subdivisions must overlap and IDs must deduplicate. Missing, inaccessible, pending and successfully processed images must remain distinguishable.
2. Download every accessible inventoried image, using refreshed signed URLs and retries. Preserve creator IDs/names, source URL, provider record, license/terms URLs, retrieved timestamp and any explicit image-specific rights. Store provider-wide policy as such; never silently assign it as an image-specific notice. Keep attribution with crops and derived features. Exact SHA-256 duplicates may share processing but retain all source/rights links. Perceptual similarity alone must not cause an image to be skipped; adjacent frames carry useful parallax.
3. Prioritize newest sequences for a first current-condition pass, then process historical images. Panoramas require perspective projection with recorded view yaw, pitch and FOV; perspective photographs need their own camera intrinsics and distortion model. Model detections are pixel observations, with model hash, prompt vocabulary, resolution and confidence. Add overlapping high-resolution tiles after benchmarking so tiny street-name panels and hydrants are not lost when resizing whole images. Run separate text-region detection/OCR and a US-sign classifier. Qwen on crops is an optional second-stage transcription/classification candidate; allow unreadable/unknown rather than completing guessed text. Keep raw transcription, normalized text, units, arrows, exceptions and supporting crops.

## Position and deduplication

4. Obtain camera intrinsics and poses, favoring computed/reconstructed positions when their accuracy is established. A heading alone is insufficient for calibrated rays. Match the same object across adjacent frames and independent passes, using appearance, text, object geometry and compatible rays. Estimate a position with robust multi-view triangulation and reprojection error checks. GPS can share a systematic offset, so evaluate against surveyed controls or authoritative local asset points. If calibration/pose is missing or rays are nearly parallel, leave the asset position unresolved or place it manually with an uncertainty label; do not use the camera point as the asset point.
5. Test metric depth as additional evidence. Relative monocular depth has scale ambiguity; even a metric model requires validation for this camera and street domain. Use object-mask depth distributions to avoid sampling background, reject depth discontinuities and compare against triangulated targets. Calibrate residual bias and scale with independently measured controls. Report horizontal uncertainty including GPS, pose, depth and matching error; model confidence is not positional accuracy. Benchmark depth-assisted and triangulation-only estimates on held-out targets before adopting depth as a positioning input.
6. Deduplicate at three levels: overlapping boxes within one view; the same object across panorama faces or adjacent frames; physical assets across sequences/providers/years. Use a candidate association graph, then constrained clustering with spatial covariance, class, OCR text/number/direction, appearance and time compatibility. Do not cluster camera locations or use a single global DBSCAN radius as the asset identity rule. Prevent chains from joining distinct nearby assets. Sign panels on one pole are separate panel assets linked to a shared support. Two nearby hydrants or opposing signs remain distinct unless positive evidence supports a merge. Persist original observations and reversible merge/split decisions; each asset links to every supporting observation and rights record.
7. Treat history as observations of asset existence and condition. Older signs may have been replaced or moved. Do not average changed signs into a current asset. Record last seen, first seen, removal/change candidates, and unresolved conflicts. Review geolocation and identity before associating regulatory signs with road approaches, incoming/outgoing edges, exceptions and time restrictions. A detected STOP sign does not create a prohibited turn by itself.

## Validation and delivery

8. Label a representative Wellesley set spanning downtown, residential roads, arterials, panorama/flat cameras, day/night, different years and object sizes. Split by street and sequence, not adjacent frames. Measure class-level detection precision/recall, OCR exact match, duplicate merge/split error, position median/95th-percentile error, review effort and image failure rates. Sample images with no detections to estimate missed assets. Manual field checks or authoritative surveyed data are needed for positional truth. Provisional acceptance targets (to be agreed after the baseline): reviewed-class precision >=95%, visible-asset recall >=90%, identity errors <=2%, and a reported class-specific location error budget; these targets are not current performance claims.
9. Review assets with multiple views, crops, OCR, dates, source attribution and a map that shows positional uncertainty. Export reviewed assets as GeoPackage/GeoJSON with persistent IDs, geometry, class/subtype, text, direction, observation dates, uncertainty, review status and evidence links. Publish separate observations, unresolved candidates, missing-coverage areas and reviewed asset layers. Keep private API credentials outside exports. Update by inventorying new imagery and revisiting changed/uncertain assets.

## Commands and current environment

GPU environment: `C:\Users\mmulq\miniconda3\envs\TDA\python.exe`, PyTorch 2.9.1+cu126, verified CUDA tensor operation and YOLO-World inference on the RTX 4060 Laptop GPU. Base Python has CPU-only PyTorch. The TDA install added detector dependencies without replacing Torch.

```
python wellesley_pipeline.py inventory --limit 0
C:\Users\mmulq\miniconda3\envs\TDA\python.exe wellesley_pipeline.py scan --limit 25
python wellesley_pipeline.py status
python wellesley_pipeline.py retry
```

`--limit 0` means all pending images for `scan`, or all pending API pages for `inventory`. The scan keeps images and crops on disk, so storage grows with the full image inventory. The current model has not been calibrated against Wellesley ground truth. Panoramic depth, triangulation, temporal identity clustering, full-image OCR/classification, high-resolution tiling and the asset-review editor remain required implementation work. The present program does not claim to have accurately mapped or deduplicated physical assets.

Inspect pilot observations: `http://localhost:8000/index.html?dataset=wellesley`. Machine-readable run status: `data/wellesley/status.json`. Durable processing database: `data/wellesley/inventory.sqlite`. Do not serve the project folder publicly; it contains a local `.env` file.
