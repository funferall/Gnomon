# Review application and benchmark

## Active scope

Ten classes are active: stop signs, speed-limit signs, one-way signs, street-name signs, generic regulatory traffic signs, traffic signals, bollards/access barriers, fire hydrants, storm drains, and manhole covers. Generic signs need a routing-role review: turn/access restrictions, speed, direction, or intersection control. Ordinary warning/advisory signs do not establish a routing restriction. Street names support network identification; hydrants, drains and covers are explicit exceptions requested for this inventory. The routing-v2 scope replaced the earlier broad street-furniture taxonomy. 878 out-of-scope observations and their crops were removed from the active dataset and retained in a local archive for provenance. Source imagery remains intact. Ordinary bus-stop signs were removed; bus-only regulatory restrictions remain traffic signs.

## Run and use

Run `python review_server.py` from this folder, then open **http://localhost:8001**. It binds to loopback and serves only the review UI, allowed image assets and its APIs. `.env`, databases and logs are not served. The original static viewer remains at `http://localhost:8000/index.html?dataset=wellesley`.

- Choose **Asset candidates**, enter reviewer initials, and filter by class, review status or score. The main view shows the boxed target and a separate enlarged crop. Correct the class, routing role and exact visible text. Accept, reject, or flag uncertainty; use **Save & next**. Accepting a classification does not automatically place an asset.
- **Left/right arrow keys** (also `<` and `>`) move between processed source images and pan to their camera coordinates. Default navigation stays in the current sequence where possible, then falls back to town chronology. Use the view selector for panorama faces. Views without detections can be browsed but are not automatically accepted as complete. The original static viewer also supports arrow navigation and map panning. Navigation respects text-entry focus and unsaved review edits.
- The layer control offers **MassGIS 2021, 2023, 2025 aerial imagery**, the **MassGIS basemap**, and OpenStreetMap. All are official Web Mercator cached services using `/tile/{z}/{y}/{x}`. Use aerial imagery to support manual placement, while noting its capture date can differ from the roadside photograph.
- Click **Place asset [P]**, then the physical location on the map; drag to adjust. Supply estimated horizontal uncertainty. Camera points are blue and remain distinct from manual asset points. Manual placement is labelled `human_placed`, not surveyed or automatically verified.
- To identify a duplicate, click an existing green asset, verify its class and choose Duplicate. Evidence links retain each observation and its rights. Undo restores the preceding saved review and association. Exports contain active manually placed assets and source/rights references. Notes and classifications are stored in SQLite, not browser-only state. Concurrent revisions produce a reload warning rather than overwriting another review.
- Shortcuts: **A** accept, **R** reject, **U** uncertain, **P** placement, **N** skip, **Ctrl+Enter** save and advance. Review navigation and source-image navigation are distinct so an asset decision always belongs to the displayed observation.

There is no multi-user authentication: this is a local prototype, not a hosted collaboration system. Full asset triangulation, uncertainty calibration, sequence matching and automatic deduplication remain future work. The app supports deliberate manual association and reversible decisions now. Visual browser automation was unavailable in this environment; API/workflow tests and JavaScript syntax checks were performed, but the interface still needs a real browser check.

## DeepSeek verification

`DEEPSEEK_API_KEY` was found in the existing environment; it is read by the verifier and never sent to the browser or stored in benchmark exports. Current official documentation confirms image input for `deepseek-flash`: https://api-docs.deepseek.com/guides/vision/ . Calls send the target crop plus a wider, red-boxed perspective view. The prompt identifies an asset independently of YOLO's proposed label, requires a routing role, rejects non-routing furniture and purely advisory warnings, forbids invented text/distance/location, and permits uncertainty. Requests are bounded by an explicit item limit and 700 output tokens. Results are cached by observation, input hash, model and prompt version. Schema-valid model output is advisory, not human ground truth; raw invalid outputs are retained separately from valid predictions. No API decision deletes a candidate or moves an asset.

```
python verify_assets.py --limit 12
python verify_assets.py --benchmark wellesley-routing-v2 --limit 100
```

A 12-item smoke test demonstrated accept/reject/uncertain verdicts and class changes. Prompt revisions showed that broad asset acceptance would admit pedestrian-warning signs, so the current regulatory-context-v3 prompt adds an explicit routing-role gate. A model may still guess, contradict its rationale, or return invalid JSON/class names; these are benchmark outcomes, not errors to hide. Older prompt versions are excluded from current review suggestions and metrics. An initial coding error caused some pilot responses not to cache; it was fixed. No claim of a measured hit rate is made without independent human labels.

## Benchmark design

The 4,000-item target is a design goal. The routing-v2 seed currently contains **340 candidate observations and 1,539 sampled full views**. It is not yet comprehensive or labelled. Candidate counts are very uneven, including only two stop-sign candidates and no storm-drain candidate at freeze time. Enrich missing classes deliberately from Wellesley imagery as scanning proceeds. Preserve frozen snapshots and give each new cohort a new benchmark ID.

1. Stratify candidates by all 10 classes, minimum box dimension (<16, 16–31, 32–63, >=64 native pixels), detector score (0.20–0.35, 0.35–0.60, >=0.60), source/camera type, capture date, blur/lighting and occlusion. Pixel size is a visibility proxy, not metric distance. Add independently measured or validated triangulated ranges in 0–5 m, 5–15 m, 15–30 m, and 30+ m bins, retaining the measurement basis and an unknown bin. Aim for sufficient independent examples per class/range, not thousands of neighboring duplicates. A reasonable eventual design is 30 examples in each class × range × three visibility conditions (3,600 candidates), plus at least 400 independently sampled full-view audits. Rare classes must be explicitly reported when this cannot be achieved.
2. Keep entire sequences in development, calibration and held-out test splits. The seed uses a deterministic sequence hash split (60/20/20); spatial street grouping, repeat passes of the same object and cross-provider duplicate checks are still needed before an honest test-set evaluation. Freeze image IDs, source hashes and prompt/model versions. Do not tune thresholds or prompts on the final test set.
3. In **Blind benchmark**, detector labels/scores and AI responses are hidden. Humans record object presence, correct class, routing role and exact legible text. Collect visibility, occlusion, distance and basis. Label a subset independently twice and adjudicate disagreements. Model output cannot serve as truth. Reject out-of-scope objects; use uncertainty for genuinely unreadable possible controls.
4. In **Full-view benchmark audit**, draw a box around every visible in-scope object, not just detector candidates. Explicitly confirm that the entire view was checked; zero-object views are valid negatives. These audits measure missed assets and false detections. The UI supports retained boxes, deletion of the most recent box and pagination. It does not yet implement second-reviewer adjudication, box editing after drawing, street-group assignment or distance uncertainty intervals.
5. Compare YOLO alone, calibration-set class-specific score thresholds, and DeepSeek crop-plus-context verification. Future experiment arms should include crop-only verification, alternative vision models and multi-view evidence. Report per-class precision, recall, rejection specificity, positive acceptance, class accuracy, exact OCR match, abstention, schema/transport failure, latency, token usage and human review time. A single aggregate “hit rate” can hide dangerous misses of turn restrictions. Use uncertainty-aware candidate routing: VLM rejection remains reviewable until a validated policy exists.
6. The reporting script computes paired-human candidate precision with Wilson confidence intervals, acceptance rate and abstention, stratified by split/class/distance/visibility. It also computes detector precision/recall from audited frames at IoU 0.25/0.5/0.75, excluding unknown-truth frames from primary metrics. It does not yet score end-to-end post-verification boxes, position accuracy, temporal identity merges, or image-region ignores. Confidence intervals assume independent examples and will be optimistic until sequence/street-cluster bootstrap is added. With no human labels it emits no fabricated accuracy. Invalid model responses need to be included in the final operational failure denominator.

```
python benchmark_assets.py prepare --name wellesley-routing-v3 --target 4000
python benchmark_assets.py report --name wellesley-routing-v2
python -m unittest discover -s tests -v
```

## Performance and false-positive improvements

Implemented: persistent detector model across batches; two-image bounded prefetch; three-view GPU microbatches; direct retention of downloaded bytes and rights sidecars; per-image phase timings; full GeoJSON export every 25 images instead of after every image; restricted routing vocabulary; reversible human decisions and cached DeepSeek verification. The source-image hash refers to actual saved bytes for the optimized pipeline. Older cached JPEGs were re-encoded and are not reused as source-byte caches without the new flag.

A local cached-panorama test used identical views and fp32 detector settings: median six-view inference time fell from about 0.415 s sequentially to 0.313 s with microbatches of three. Detection count stayed eight in all three runs of each mode; equal counts do not prove identical boxes or accuracy. Two initial optimized live batches took 30.0 s and 28.9 s for 25 mixed images each (about 1.2 s/image excluding initial model load). This is not a controlled comparison with the earlier panorama-only 2.9 s/image estimate; image mix, API latency and background work differ. `timings.jsonl` and `batch_timings.jsonl` retain actual measurements.

Next accuracy work: class-specific threshold calibration, US regulatory-sign subclasses, exact duplicate source-hash processing reuse, shape/text validation and repeated-view consistency checks. Far/small sign evaluation needs higher-resolution source imagery and tiled inference: a 2048-pixel-wide panorama has limited pixels per direction, and upscaling faces cannot recover missing text. Avoid discarding low-score controls or all sky/ground views until recall is measured; drains and manhole covers need ground-facing views. Speed improvements must be assessed alongside missed-object rates, not just throughput.
